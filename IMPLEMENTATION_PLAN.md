## Phase 3: Hardening bundle (three commits, in this order)

### 3a. SEC-01: JSON script block breakout and attribute escaping

Files: `_layouts/error.html`, `_layouts/default.html`, `test/test_rendered_site.rb`.

- In the `<script type="application/json" id="error-lang-i18n">` block, apply `| replace: '<', '<'` to each jsonified value. `error.js` reads it with `JSON.parse` and writes with `.textContent`, so the encoding is decoded and safe.
- **Do not** HTML-escape the values inside the JSON block (it would double-encode through `.textContent`).
- Apply `| escape` only where a value is rendered as HTML text or an attribute (error titles/messages, button labels, skip-link text) in `error.html` and `default.html`.
- Tests: a locale string containing `</script><img onerror=...>` leaves no raw `<` inside the JSON block, is escaped in HTML positions, and the error page still localizes.

### 3b. SEC-05: Ruby engine and plugin safety (owns the shared `lang` rule)

Files: `lib/jekyll-theme-resume/resume_validator.rb`, `_plugins/resume_pages_generator.rb`, `test/test_resume_validator.rb`.

- Remove the legacy fallback in `load_yaml_file` (`rescue ArgumentError` → `YAML.load_file(file_path)`, around lines 393–395).
- At the YAML rescue sites (`load_site_config` ~243, `read_locale_file` ~257, data files ~384): keep the `Psych::SyntaxError` branch **first** (it reports line/column), then add `Psych::Exception` (bad aliases, disallowed classes) with a friendly error. `SyntaxError` is a subclass of `Exception`, so order matters.
- Define **one** language-key pattern, `/\A[a-zA-Z0-9_-]+\z/`, as a constant in the validator. Validate `site.languages` keys against it before any `File.join`/glob, and reuse the same check in `ResumePagesGenerator` (skip with a warning, same style as its existing warnings).
- Tests: bad alias → friendly error not crash; `../x` and `a/b` language keys rejected before filesystem use; valid keys (`en`, `zh-CN`, `pt_BR`) pass.

### 3c. SEC-03: contextual escaping in attributes and scripts

Files: `_includes/analytics-head.html`, `_layouts/resume.html`, `_layouts/profile.html`, `_layouts/default.html`, `_includes/hreflang.html`, validator, tests.

- `lang="{{ lang }}"` (resume, profile, default) and `hreflang="{{ t.lang }}"` pass through `| escape`.
- Liquid has no regex, so analytics IDs are enforced in two places:
  - **Validator:** `analytics.gtm` must match `\AGTM-[A-Z0-9]+\z`; `analytics.gtag` must match `\A[A-Za-z0-9-]+\z` (covers `G-`, `AW-`).
  - **Template defense in depth:** emit IDs into JS with `| jsonify` and into URLs with `| url_encode`, instead of raw `'{{ ... }}'`.
- The `lang` key pattern is **not** re-implemented here; it comes from 3b.
- Tests: an ID containing `'`, `</script>` or whitespace is reported by the validator and cannot break the script; `lang` values with quotes are escaped in rendered HTML.

## Phase 4: SEC-02: safe URL schemes (one commit)

Files: `_includes/avatar.html`, `_includes/social-links.html`, `_includes/language-switcher.html` (check), validator, `test/test_resume_validator.rb`, `test/test_rendered_site.rb`, `docs/reference/config.md`.

**Rule (one definition, used by validator and templates):** trim and downcase the value. If it contains `:`, it must start with an allowed scheme; otherwise it is a plain relative path and is allowed (`assets/me.jpg` and `/assets/me.jpg` both keep working; `_config.sample.yml` documents the former).

| Setting | Allowed schemes |
|---|---|
| `avatar_url` (image `src`) | `http`, `https` |
| `avatar_link` | `http`, `https`, `mailto`, `tel` |
| `social_links.email` | bare address, or `mailto:` |
| other `social_links.*` | `http`, `https` (`whatsapp` is a URL such as `https://wa.me/...`; there is no phone-digits form) |

- **Validator:** a violation is an error naming the setting and value (`javascript:`, `data:`, `vbscript:`, `file:` all fail).
- **Templates:** a violating link/image is silently not emitted. This is the real protection, because the demo runs with `validate_resume_strict: false`.
- Keep the scheme list in one spot per language of implementation (Ruby constant, one Liquid assign) so adding a scheme later is a one-line change.
- Tests: each bad scheme is rejected by the validator and omitted from rendered HTML; `https://`, `mailto:`, relative paths, `JavaScript:` with mixed case and padded whitespace all behave correctly.
